Implement the update computation of one Muon optimizer step. Muon (Keller Jordan, 2024) is the optimizer used to train Moonlight and Kimi K2; instead of scaling each gradient coordinate independently like AdamW, it orthogonalizes the whole momentum-updated gradient matrix, so every singular direction of the update contributes almost equally. Given a gradient matrix G and the optimizer's momentum buffer Buf, compute the orthogonalized, rescaled update and write it to output. All tensors are float32.

First combine the buffer and the gradient into the update direction \[ V = \text{momentum} \cdot Buf + G \] then orthogonalize V with 5 steps of the quintic Newton–Schulz iteration. With \(X_0 = V / (\|V\|_F + 10^{-7})\), each step computes \[ A = X X^{T}, \qquad B = b A + c A^{2}, \qquad X \leftarrow a X + B X \] with coefficients \(a = 3.4445\), \(b = -4.7750\), \(c = 2.0315\). The normalization makes the largest singular value of \(X_0\) at most 1 (since \(\sigma_{\max} \le \|X_0\|_F = 1\)), and the polynomial \(p(s) = a s + b s^{3} + c s^{5}\) maps the singular values into a band around 1: the quintic has no fixed point at \(s = 1\) (\(p(1) = 0.701\)) and is tuned to lift small singular values quickly. For rectangular inputs, the singular values of \(X\) after 5 steps lie roughly in \([0.68, 1.13]\); square Gaussian inputs keep some singular values well below that band (measured as low as 0.001–0.02 at 1024 × 1024), because a square Gaussian matrix has singular values near 0 that 5 steps do not lift. \(X\) is therefore an approximation of the orthogonal polar factor of \(V\) by design — exactly as in Keller Jordan's and PyTorch's Muon implementations — and the 5-step iteration itself defines the expected result, not the exact polar factor. Finally, scale by \(\sqrt{\max(M, N)}\), the convention fixed by this challenge: a semi-orthogonal matrix has RMS \(1 / \sqrt{\max(M, N)}\), so the scaled update has RMS 1. (Other Muon implementations scale differently — PyTorch's Muon uses \(0.2 \cdot \sqrt{\max(M, N)}\) and Keller Jordan's current code uses \(\sqrt{\max(1, M / N)}\) — but \(\sqrt{\max(M, N)}\) is the spec here.) \[ output = X \cdot \sqrt{\max(M, N)} \]

Scope. This challenge computes the Muon update direction only: there is no parameter update, no weight decay, and no Nesterov momentum. Correctness is judged against the float32 5-step Newton–Schulz iteration specified above, not against the exact SVD polar factor of \(V\).

Implementation Requirements

Implement solve(G, Buf, output, M, N, momentum):

  • G: shape (M, N), the current gradient of a weight matrix; it is a read-only input and must not be modified
  • Buf: shape (M, N), the momentum buffer; it is a read-only input and must not be modified
  • output: shape (M, N), the orthogonalized update
  • M, N: the dimensions of the weight matrix
  • momentum: the momentum coefficient used to combine Buf and G
  • Use only native features of the framework you choose (no external libraries); keep the function signature unchanged
  • Write the result into output; every entry of output must be written
  • Run exactly 5 Newton–Schulz steps with the coefficients above; when M > N, the iteration may equivalently be run on the transposed matrix so the Gram matrix X XT is formed on the smaller dimension
  • All matrix-multiplication inputs and accumulations must be float32 or higher precision (no TF32, float16 or bfloat16 operands); reduced-precision matrix multiplication does not meet the tolerance

Example

Input: M = 2, N = 3, momentum = 0.9: \[ G = \begin{bmatrix} 0.5 & -1.0 & 2.0 \\ 1.0 & 0.0 & -0.5 \end{bmatrix}, \quad Buf = \begin{bmatrix} 0.1 & 0.2 & 0.0 \\ -0.3 & 0.4 & 0.1 \end{bmatrix} \] \[ V = 0.9 \cdot Buf + G = \begin{bmatrix} 0.59 & -0.82 & 2.0 \\ 0.73 & 0.36 & -0.41 \end{bmatrix} \] Output: \[ output = \begin{bmatrix} 0.5427371 & -0.4092258 & 1.1156158 \\ 1.7146817 & 0.5666907 & -0.3777507 \end{bmatrix} \]

Constraints

  • All tensors are float32
  • 1 ≤ M ≤ 1,024
  • 1 ≤ N ≤ 1,024
  • 0 ≤ momentum < 1
  • Entries of G and Buf are drawn from a standard normal distribution in the tests, apart from dedicated edge cases with all-zero and 1e-8-magnitude inputs
  • Performance is measured with M = 1,024, N = 1,024, momentum = 0.9
