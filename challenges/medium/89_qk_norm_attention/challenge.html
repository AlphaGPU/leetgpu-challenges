Implement multi-head self-attention with QK-Normalization: before the attention scores are computed, apply RMSNorm along the head dimension to each token's per-head query and key vectors. This variant appears in modern language and vision models (e.g. Chameleon, Gemma-3, OLMo, ViT-22B) where it dramatically improves training stability.

Inputs are float32 tensors: Q, K, and V each have shape (N, d_model), where N is the sequence length and d_model is the model dimension. The model is split into h heads of dimension d_head = d_model / h. The learned RMSNorm scale vectors q_weight and k_weight each have shape (d_head,) and are shared across all heads and tokens. Attention is non-causal (every token attends to every token).

Reshape Q, K, V from (N, d_model) to (N, h, d_head) so each row holds one vector per head. For every token i and head t, normalize the length-d_head vectors:

\[ \begin{aligned} \text{rms}^Q_{i,t} &= \sqrt{\tfrac{1}{d_{\text{head}}}\sum_{j=0}^{d_{\text{head}}-1} Q_{i,t,j}^{\,2} + \varepsilon}, & \hat{Q}_{i,t,j} &= \tfrac{Q_{i,t,j}}{\text{rms}^Q_{i,t}} \cdot \text{q\_weight}_j \\[6pt] \text{rms}^K_{i,t} &= \sqrt{\tfrac{1}{d_{\text{head}}}\sum_{j=0}^{d_{\text{head}}-1} K_{i,t,j}^{\,2} + \varepsilon}, & \hat{K}_{i,t,j} &= \tfrac{K_{i,t,j}}{\text{rms}^K_{i,t}} \cdot \text{k\_weight}_j \end{aligned} \]

Then, independently for each head t \(\in \{0,\dots,h-1\}\), compute scaled dot-product attention:

\[ S_{t,i,j} = \frac{\hat{Q}_{i,t,:}\;\cdot\;\hat{K}_{j,t,:}}{\sqrt{d_{\text{head}}}}, \quad A_{t,i,j} = \frac{\exp(S_{t,i,j})}{\sum_{k=0}^{N-1} \exp(S_{t,i,k})}, \quad O_{i,t,:} = \sum_{j=0}^{N-1} A_{t,i,j} \; V_{j,t,:} \]

Finally concatenate the per-head outputs back into (N, d_model) and write to output.

Implementation Requirements

  • Use only native features (external libraries are not permitted).
  • The solve function signature must remain unchanged.
  • The final result must be stored in the output tensor.
  • RMSNorm reduces along the head dimension (length d_head), not across heads.
  • q_weight and k_weight are shared across all tokens and heads.
  • Attention is non-causal: every query attends to every key.
  • d_model is always divisible by h.

Example

With N = 2, d_model = 4, h = 2 (so d_head = 2), eps = 1e-6:

Input:
  Q        = [[1.0,  0.0,  2.0,  3.0],
              [0.5, -1.0,  0.0,  2.0]]
  K        = [[1.0,  1.0,  0.0,  1.0],
              [0.0,  1.0,  2.0, -1.0]]
  V        = [[0.5,  1.0,  1.5,  2.0],
              [2.5,  3.0,  3.5,  4.0]]
  q_weight = [1.0, 1.0]
  k_weight = [1.0, 1.0]

Output ≈ [[1.0379, 1.5379, 2.0374, 2.5374],
          [1.1125, 1.6125, 1.7288, 2.2288]]

Constraints

  • 1 ≤ N ≤ 4,096
  • 2 ≤ d_model ≤ 4,096
  • 1 ≤ h ≤ 64, and d_model is a multiple of h
  • Q, K, V, q_weight, k_weight, and output are float32
  • eps is a small positive float32 (e.g. 1e-6)
  • Performance is measured with N = 2,048, d_model = 2,048, h = 16
