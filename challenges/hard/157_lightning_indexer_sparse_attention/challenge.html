Implement one decode step of indexer-driven sparse attention, the scheme used by DeepSeek Sparse Attention: a cheap int8 “lightning indexer” scores every cached token, only the topk highest-scoring positions are kept, and the new token's query heads attend to those positions only. Fuse the indexer, the top-k selection and the attention so the full key/value cache is never read. Each of the B sequences has its own cache of S tokens with one key/value head of size D shared by all H query heads (multi-query attention).

Implementation Requirements

Implement solve(q, k_cache, v_cache, idx_q, idx_k, idx_w, output, B, S, H, D, H_I, D_I, topk):

  • q: shape (B, H, D), float32, the new token's query heads
  • k_cache, v_cache: shape (B, S, D), float32
  • idx_q: shape (B, H_I, D_I), int8, the indexer query heads
  • idx_k: shape (B, S, D_I), int8, the indexer key of every cached token
  • idx_w: shape (B, H_I), int8, the per-head indexer weights (may be negative)
  • output: shape (B, H, D), float32

For each sequence b, the indexer score of position s is \[ I_{b,s} = \sum_{j=0}^{H_I - 1} \text{idx_w}_{b,j} \cdot \max\!\Big(0,\ \sum_{d=0}^{D_I - 1} \text{idx_q}_{b,j,d}\, \text{idx_k}_{b,s,d}\Big) \] Every term is an integer and \(|I_{b,s}| \le 2^{23}\), so the scores are exact in int32 and in float32. Let \(n = \min(\text{topk}, S)\). The selected set \(P_b\) is the \(n\) positions with the largest \(I_{b,s}\); among equal scores, the lower position is selected first. Then for every query head h: \[ \text{output}_{b,h} = \sum_{s \in P_b} \frac{e^{\ell_{h,s}}}{\sum_{s' \in P_b} e^{\ell_{h,s'}}}\, \text{v_cache}_{b,s}, \qquad \ell_{h,s} = \frac{q_{b,h} \cdot \text{k_cache}_{b,s}}{\sqrt{D}} \] Each selected position is attended exactly once; when topk ≥ S, every position is selected.

  • Use only native features of the framework you choose (no external libraries); keep the function signature unchanged
  • Write the result into output; the inputs must not be modified
  • The softmax must be numerically stable for attention logits in the hundreds (subtract the row maximum)

Example

Input: B = 1, S = 4, H = 1, D = 2, H_I = 1, D_I = 2, topk = 2, q = [1, 0], idx_q = [1, 2], idx_w = [3]. Rows are positions: \[ \text{k_cache} = \begin{bmatrix} 1 & 0 \\ 0 & 1 \\ 2 & 0 \\ 0 & 2 \end{bmatrix}, \quad \text{v_cache} = \begin{bmatrix} 1 & 2 \\ 3 & 4 \\ 5 & 6 \\ 7 & 8 \end{bmatrix}, \quad \text{idx_k} = \begin{bmatrix} 2 & 1 \\ 0 & 1 \\ -1 & 0 \\ 0 & 1 \end{bmatrix} \] The indexer dot products are [4, 2, -1, 2], so \(I = 3 \cdot [4, 2, 0, 2] = [12, 6, 0, 6]\). Position 0 is selected first; positions 1 and 3 tie at 6 and the lower position, 1, wins, so \(P = \{0, 1\}\). The attention logits are \(\ell = [1/\sqrt{2}, 0]\), giving weights \([0.6697615, 0.3302385]\) and \[ \text{output} = 0.6697615 \cdot [1, 2] + 0.3302385 \cdot [3, 4] = [1.6604769, 2.6604769] \]

Constraints

  • 1 ≤ B ≤ 8; 1 ≤ S ≤ 65,536; 1 ≤ topk ≤ 4,096
  • 1 ≤ H ≤ 64; 1 ≤ D ≤ 256; 1 ≤ H_I ≤ 64; 1 ≤ D_I ≤ 128
  • -8 ≤ idx_q, idx_k ≤ 8; -16 ≤ idx_w ≤ 16
  • q, k_cache, v_cache values lie in [-150, 150], [-1, 1] and [-1, 1]
  • Performance is measured with B = 4, S = 65,536, H = 32, D = 128, H_I = 64, D_I = 128, topk = 2,048
